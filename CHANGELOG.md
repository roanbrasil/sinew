## [Unreleased]

### Added

- Playground in `sinew-scope` (#84). `POST /api/playground/run` renders raw messages or a prompt-hub version (`name@tag`, with `{variable}` values; the version's `model_config` fills in models, temperature and max tokens) and runs several `provider:model` specs concurrently, returning or streaming (Server-Sent Events: `start`, `delta`, `result`, `done`) each model's output with latency, time to first token, tokens and cost; `temperature` and `tools` are dropped for models whose `capabilities()` do not support them, and per-model failures do not fail the request. Models are built on the server with `from_spec` and the server's API keys; only local providers (Ollama, LM Studio, llama.cpp, vLLM, ...) are allowed unless `--playground-providers` (or `SINEW_SCOPE_PLAYGROUND_PROVIDERS`, `PlaygroundConfig::allow_providers`) lists more, and custom endpoint URLs are refused. Every run is traced under the `playground` project with its invocation parameters. `GET /api/playground/models` lists the allowed providers, registered models and the models allowed local servers report; `GET /api/runs/{id}/playground` returns the inputs of a stored LLM run (Sinew or OpenTelemetry GenAI) to prefill the editor. `ServerConfig::playground` takes a `PlaygroundConfig` (`with_model` registers a model under a spec for tests, `with_model_factory`, `max_models`, `timeout`, `project`, `discover_models`). Web UI: a Playground page (message editor, detected variables, model multi-select, options, side-by-side streamed outputs with metrics, "Save as prompt version") and "Open in playground" on LLM runs and prompt versions. Guide: [docs/scope.md](docs/scope.md#playground).
- Fuzz targets for the parsers of untrusted input (#96): a cargo-fuzz workspace in `fuzz/` (`publish = false`, excluded from the main workspace) with 16 targets: `sse_parser` (chunked parsing equals one-shot parsing), `stream_anthropic`, `stream_openai`, `stream_gemini`, `structured_json` (JSON extraction, schema validation, list parsing, tool-call arguments from partial JSON deltas), `json_rpc_mcp` and `json_rpc_a2a` (in-process servers always answer with a valid JSON-RPC response, or none for notifications), `loader_html`, `loader_csv`, `loader_json`, `loader_markdown`, `otlp_json`, `otlp_proto`, `redactor` and `guardrails` (idempotent redaction, no secret left behind) and `tool_args` (`#[tool]` argument parsing). Seeds in `fuzz/seeds/` and minimized reproducers in `fuzz/regressions/` are replayed on stable by `cargo test --manifest-path fuzz/Cargo.toml`. Workflow `.github/workflows/fuzz.yml`: replay on pushes and pull requests that touch `crates/` or `fuzz/`, and a nightly (and on-demand) run of every target with debug assertions, a cached corpus and crash files uploaded as artifacts. Internal parsers are reached through `#[doc(hidden)] __fuzz` modules in `sinew-core` and `sinew-rag` (not public API). Guide: [CONTRIBUTING.md](CONTRIBUTING.md#fuzzing), [docs/testing.md](docs/testing.md#fuzzing-sinews-parsers).

- RAG evaluation in `sinew-eval`, module `rag` behind the new `rag` feature (on with `eval` + `rag` in `sinew`) (#79). `RagSample` (question, ranked contexts with ids, answer, optional reference and relevant ids; `from_answer`, `from_documents`, `from_eval`, `to_output`, `rag_output`). LLM-judged metrics following RAGAS: `Faithfulness` (claim extraction, then per-claim verification), `AnswerRelevance` (judge grade, or `from_generated_questions` with embeddings and a noncommittal check), `ContextPrecision` (average precision of judged-useful contexts), `ContextRecall` (reference statements attributable to the contexts) and `CitationAccuracy` (`[n]` markers checked against the cited passage). Embedding metric `AnswerSimilarity` (optional threshold). Retrieval metrics without a model: `RetrievalMetric::{hit_rate, recall, precision, mrr, ndcg}` and the functions `hit_rate_at_k`, `recall_at_k`, `precision_at_k`, `reciprocal_rank`, `ndcg_at_k`. Each returns a `MetricResult` (score, reason, details, `JudgeUsage` with calls, tokens and cost) through the `RagMetric` trait and is an `Evaluator` for `Experiment`s (`RagEvaluator` wraps custom metrics). `TestsetGenerator` writes factual and multi-hop question / reference answer / source id triples from documents with any `ChatModel` (seeded document order, word-overlap deduplication, failures collected) and `Testset::to_dataset` exports them. Sample 15 prints the metrics for a synthetic test set. Guide: [docs/evaluation.md](docs/evaluation.md#evaluating-rag).
- OAuth 2.1 for MCP over Streamable HTTP, per the MCP authorization specification (#11). Server (feature `oauth-server` on `sinew-mcp`): `McpHttpConfig::with_oauth(OAuthConfig)` serves protected resource metadata (RFC 9728) at `/.well-known/oauth-protected-resource` and the resource-specific path, answers `401` with `WWW-Authenticate: Bearer resource_metadata="..."` (`error="invalid_token"` for rejected tokens), validates JWT access tokens with `oauth::JwtValidator` (RS/PS/ES/EdDSA signatures against the issuer's JWKS from `jwks_uri` or RFC 8414 / OpenID Connect discovery, cached with refetch on unknown `kid` at a bounded rate; `alg: none` and HMAC refused; issuer, audience, `exp`/`nbf` with leeway, claim types), and enforces required and per-tool scopes (`with_required_scopes`, `with_tool_scopes`, `403 insufficient_scope`); `503` when keys are unavailable. Client (feature `oauth-client`): `oauth::OAuthClient` discovers the resource and authorization server metadata from the `401`, registers dynamically (RFC 7591) or uses a configured client, runs the authorization code flow with PKCE S256 and the RFC 8707 `resource` parameter through a callback-free API (`begin() -> (url, state)`, `complete(code, state)`, `complete_redirect(url)`), and refreshes tokens; `McpClient::connect_http_with_oauth(url, TokenProvider)` attaches the token, refreshes before expiry and retries once after a `401`. `TokenStore` trait with `InMemoryTokenStore`; `TokenSet`, `ClientRegistration` and `Pkce` redact secrets in `Debug`. Feature `oauth` enables both; umbrella feature `mcp-oauth` on `sinew`. New optional dependencies: `jsonwebtoken` 9 (ring backend), `ring`, `base64`. Guide: [docs/mcp.md](docs/mcp.md#oauth-21-public-mcp-servers), with a Keycloak docker compose example.
- Built-in tool library, new crate `sinew-tools` (feature `tools` on `sinew`, re-exported as `sinew::builtin_tools`) (#70), one cargo feature per family: `calculator` (expression parser over `f64`, no code execution), `datetime` (`current_time`, `date_add`, `date_diff` with IANA time zones via jiff), `web-search` (`web_search` over Tavily, Brave Search or SearXNG; keys from config or `TAVILY_API_KEY` / `BRAVE_SEARCH_API_KEY` / `SEARXNG_URL`), `web-fetch` (`web_fetch`: Readability extraction to Markdown with dom_smoothie, byte and character limits), `wikipedia` (`wikipedia_search`, `wikipedia_summary`), `http` (`HttpRequestTool`: requests restricted to allow-listed hosts and methods, fixed credential headers, `side_effects()` when an unsafe method is enabled, `Idempotency-Key` from the durable call key), `email-smtp` (`send_email` with lettre, recipient allow-list, Message-ID from the idempotency key) and `email-imap` (`email_list`, `email_read`, read-only with `EXAMINE` and `BODY.PEEK`). `sinew_tools::net::HostPolicy` is the shared SSRF guard: allow-/deny-lists of hosts, no loopback, private, link-local, CGNAT or reserved addresses (IPv4-mapped and NAT64 included), enforced by a DNS resolver that drops non-public answers, on every redirect, with environment proxies ignored. Every network tool is tested offline against recorded responses. Guide: [docs/builtin-tools.md](docs/builtin-tools.md).
- Context engineering toolkit (`sinew_core::context`, #68): strategies over `Vec<Message>` that keep tool calls and their results paired. `KeepLast` (last N messages, last N tokens or `fit_budget()`, system messages always kept, `start_on_user`), `ClearToolResults` (replaces used tool results with a placeholder naming the tool and size, or `truncate_to(n)`; stops once the budget fits), `Summarize` (folds older turns into one running summary message with any `ChatModel`, configurable prompt and header, updated incrementally from a stored summary or a prefix-hash cache, chunked by `max_chunk_tokens`), `SemanticSelect` (keeps older turns most similar to the latest user message through the `TextEmbedder` trait or `embedder_fn`; `sinew_rag::embeddings::ContextEmbedder` adapts `Embeddings`). `ContextPolicy` chains strategies against a token budget and returns a `ContextReport`; `ContextPolicy::trimming` and `summarizing` presets. `TokenCounter` (default `EstimateCounter` on `pricing::estimate_tokens`; closures work), `ContextStrategy`, `ContextBudget`, `message_groups`, `check_tool_pairing`, `drop_unpaired_tool_messages`, `render_transcript`. `ReactAgent::context_policy` applies a policy before each model call without changing the state, `persist_context(true)` stores the result, and a `context_policy` custom event reports token counts. Benchmark `cargo bench -p sinew-core --bench context`. Guide: [docs/context.md](docs/context.md).
- Guardrails as composable runnables (#14): `sinew_core::guardrails` with the `Guardrail` (sync) and `AsyncGuardrail` traits, `GuardrailStage` and `GuardrailVerdict` (moved from `sinew-harness`, which re-exports them unchanged); built-in `PiiRedactor`, `SecretRedactor`, `InjectionDetector` (now with `.at(stages)`), `DenyList` (keywords, topics, regexes; block or redact), `JsonSchemaGuard`, `MaxLength` (block or truncate) and `LlmJudge` (any `ChatModel`, policy prompt, structured `allow`/`reason` verdict). Per-rule actions with `GuardRule`/`guard(g)`: `redact` (default), `block`, `refuse(message)`, `warn` and `retry(n)` (the model is asked again with the reason, bounded per rule). `ChatModelExt::with_guardrails(input, output)` returns `Guarded<M>`, a `ChatModel` that checks new user messages and tool results, then the answer; `chat_with_report` returns a `GuardReport`; `StreamGuardMode::{Buffer, Final}` for streams. `Guardrails::step(stage)` is a `Runnable` (`GuardStep`) for chains. `ReactAgent::tool_guardrails` checks tool results before the model sees them and emits `guardrail` custom events. `GuardEvent`s go to an observer; `sinew_trace::guardrail_observer` and `record_guard_event` record them as trace runs. New `Error::Guardrail { guard, stage, reason }`. The PII, secret and injection patterns live in `sinew_core::guardrails::patterns`; `sinew_trace::redact` re-exports them. `sinew-core` now depends on `regex`. Guide: [docs/guardrails.md](docs/guardrails.md).
- Long-term memory, new crate `sinew-memory` (feature `memory` on `sinew`) (#13): `MemoryManager` over any `Store` (`InMemoryStore`, `SqliteStore`, your own) with one namespace per user (`["memories", user]`). `remember` extracts facts, preferences and episodes from a conversation with any `ChatModel` through structured output (configurable prompts), drops exact duplicates, and lets the model add, update or delete against the most similar existing memories; `recall(query, k)` ranks by cosine similarity with `sinew_rag::Embeddings` (vectors stored with each memory, re-embedded when the model changes) or by keyword overlap without; `add`, `put`, `get`, `list`, `forget`, `forget_all`, `context`. `Memory` has id, content, kind, timestamps, source thread and importance. `MemoryAgent` wraps a `ReactAgent`: it recalls before each turn and saves the turn after the run, in the background by default (`flush`). `MemoryHook` (feature `harness`) does the same for `sinew-harness`. `ReactAgent::system_context` appends per-call system text computed asynchronously; it runs before `context_policy` (so it counts against the budget) and is never stored in the state, even with `persist_context`. Guide: [docs/memory.md](docs/memory.md).
- Guide: [running in production](docs/production.md) with a copyable readiness checklist (#55).
- Model router (`sinew_core::router`): `Router` is a `ChatModel` that picks one of several named routes per request. Rules over the request (`RouteInput::estimated_tokens`, `has_tools`, `has_images`, ...) and caller `RouteHints` such as the tenant tier (`Router::chat_with_hints`); an optional `Classifier` (a small model labels the request through structured output); a capability guard so requests with images, documents, audio or tools only reach routes that support them; a cascade (`cascade(["cheap", "strong"], Validator)`) that escalates when the answer fails `Validator::non_empty`, `no_refusal`, `structured` or a custom check, counted by `Router::escalations`; a per-route `CircuitBreaker` (consecutive failures open the route for a cool-down, then half-open) and latency EWMA to prefer the faster of equivalent routes; `on_route` callback with `RouteDecision`, `Router::route` dry run and `Router::stats`. `capabilities()` is the union of the routes'; streams are routed once and not cascaded. `StructuredOutput::parse_message` checks a reply without calling a model (#34). ### Fixed

- `SseParser`: an empty chunk between a `\r` and its `\n` made the `\n` a second line ending, splitting one event in two (found by the `sse_parser` fuzz target, #96).
- Anthropic and Gemini decoders (streaming, non-streaming, Anthropic batch status): token counts near `u32::MAX` overflowed when summed (a panic in debug builds) and counts above it were truncated; they now saturate, also for OpenAI-compatible usage (#96).
- `sinew-trace` OTLP protobuf decoder (`proto::decode_request`, used by `sinew-scope` ingest): nested `arrayValue` / `kvlistValue`s recursed without a limit, so a small request could overflow the stack; nesting deeper than 32 levels is now an error (#96).
- `html_to_text` (`HtmlLoader`): text with many `<` and no later `>` took quadratic time; it is now linear with the same output (#96).

- `OpenAiCompat::ollama` accepts an `OLLAMA_HOST` ending in `/v1` (it produced `/v1/v1`), like `from_spec("ollama:...")`.
- `sinew-scope`: opening a database that needs schema migrations could panic in sqlx (`index out of bounds`) when a pooled connection had cached a statement prepared before the `ALTER TABLE`; migrations now run on a separate connection.
- Bugs found while raising test coverage (#139):
  - `sinew-core`: a `Retry-After` header with a huge number of seconds (e.g. `1e30`) panicked inside `Duration::from_secs_f64`; it now saturates to `Duration::MAX` (capped by `RetryPolicy::with_max_retry_after`).
  - `sinew-core`: `Error::is_retryable` returned `false` for a connection dropped while reading a response body (e.g. an SSE stream cut midway), although connection errors are documented as retryable.
  - `sinew-core`: Anthropic `batch_status` and `batch_results` mapped HTTP errors with `error_for_status`, losing the error body and `Retry-After`; they now return `Error::Provider` / `Error::RateLimited` like every other provider call.
  - `sinew-core`: `providers::capabilities_for` matched the provider name case-sensitively (`"Ollama"` gave `None`) while `from_spec` does not.
  - `sinew-serve`: `GET /threads?status=busy` (and `POST /threads/search`) never matched, because `busy` comes from the runs in flight and is not stored, and `status=idle` listed busy threads; the filter now applies to the effective status before paging.
  - `sinew-scope view`: a trace id with multi-byte characters could panic (cut at byte 8), run names were printed lowercased, and token totals could overflow `u32`.
  - `sinew-agent`: `--max-steps` above `u32::MAX` silently wrapped (`4294967297` became `1`); it is now rejected.

### Changed

- CI coverage: samples are now actually excluded from the report (`--exclude-from-report 'samples/*'` matched no package and is rejected by `cargo llvm-cov report`, an error the job hid behind `| tee`), and the job fails below 85% line coverage (`--fail-under-lines 85`). New offline tests for provider HTTP errors and streams cut midway, the Qdrant store and embedding clients against local mock servers, `sinew-scope` and `sinew-serve` API error paths, and the `sinew-scope` / `sinew-agent` command lines (#139).

- `sinew-harness`'s `http_fetch` uses the `sinew-tools` SSRF guard (#70): with `allow_private` off (the default), host names that resolve to loopback, private or link-local addresses, redirects to such addresses, IPv4-mapped IPv6 literals and CGNAT / reserved ranges are now refused, and proxies from the environment are no longer used. `HttpOptions` is unchanged.
- CONTRIBUTING.md documents the protected-branch workflow and commit signing; `.github/CODEOWNERS` added (#104).
- Releases are automated with release-plz and crates.io trusted publishing; see [RELEASING.md](RELEASING.md) (#101).
- Tool parameter schemas from `TypedTool` and `#[tool]` inline nested types instead of using `$ref`/`$defs`, which several providers reject.
- Samples 03 and 22 use `#[sinew::tool]`.
- `sinew-harness`: loop detection is on by default (see above).
- `ReactAgent`: the `tools` node now routes with `Command::goto("agent")` instead of a static edge.
- `sinew-harness`: `PiiRedactor` only masks Luhn-valid card numbers that start with 2–6, so Luhn-valid identifiers and millisecond timestamps starting with 1 are kept (#45).

- `sinew-core`: multimodal messages (images, PDF, audio), LCEL-style `Runnable` pipelines and output parsers, retry / fallback / rate-limit / timeout / response-cache wrappers, token cost table, Azure OpenAI, shared tuned HTTP client.
- `sinew-graph`: `Command`, dynamic `interrupt()` and resume, `interrupt_after`, subgraphs, time travel (history, replay, fork), node retry / cache / timeout, long-term `Store`, stream modes, supervisor and swarm multi-agent prebuilts.
- `sinew-checkpoint`: checkpoint ids and namespaces (with in-place migrations), `SqliteStore`.
- New crates: `sinew-rag` (retrieval), `sinew-harness` (agent harness and `sinew-agent` CLI), `sinew-serve` (deployment server, OpenAI-compatible endpoint), `sinew-a2a` (Agent2Agent 0.3).
- `sinew-scope`/`sinew-trace`/`sinew-eval`: prompt hub, feedback and annotation queues, cost and TTFT tracking, monitoring dashboards, online evaluator rules and alerts, OTLP export (JSON and protobuf), full-text run search, retention, pairwise experiments.
- `sinew-mcp`: Streamable HTTP server transport (`McpServer::http_router`, `serve_http`, `McpHttpConfig`: sessions or stateless, bearer auth, origin allow-list, health route); HTTP client with token or custom headers.
- `sinew-core`: `AsyncFnTool` (async closures) and `TypedTool` (schema derived from the argument type, feature `schemars`).
- Samples 14–22; umbrella features `rag`, `harness`, `serve`, `a2a`, `otlp`.
- Per-crate READMEs, logo, banner; workspace lints (`unsafe_code = "forbid"`), release profile with thin LTO; CI on Linux and macOS, docs, MSRV and cargo-deny.

### Changed

- Breaking: `Message` and `Usage` have new fields, `Error` gains `RateLimited`, `Timeout` and `Other`, `GraphEvent`/`RunOutcome::Interrupted` carry `interrupts`, and new `GraphEvent` variants exist; use `..` / `..Default::default()` in patterns and literals.
- Anthropic and Gemini `input_tokens` now include cached and tool-use prompt tokens, matching OpenAI.

### Security

- `pdf-extract` 0.12 (lopdf 0.42) fixes RUSTSEC-2026-0187. RUSTSEC-2026-0459 (bundled SQLite) is acknowledged until the `sqlx` 0.9 upgrade.
